# 仓库职责与文件边界

## 公共 Skill 仓库

本仓库只维护可在多个软件项目重复使用的：技能入口、创建与复核流程、通用模板、法规来源索引、交存生成工具、检查脚本和非敏感测试样例。此仓库可以公开，不应放入任何具体项目的正式申请文件或源代码。

`SKILL.md` 只负责任务路由；各类任务的详细规则放在 `prompts/` 和 `references/`；生成工具在 `scripts/`；模板在 `assets/templates/`；回归测试在仓库根目录 `tests/`。

## 项目专属私有仓库

具体软件的申请表、设计说明书、源程序鉴别材料、真实源码证据索引、申报事实与权属核验表、历史文件及审查记录应保存在**单独的私有仓库**。

两个仓库允许相互通过 URL 提供工作说明，但不得以复制的方式把公司源代码、内网地址、令牌、个人信息或者研发记录带入本公共仓库。

## 推荐分工

1. Skill 提供分析和生成方法，并核查技术内容是否具有代码依据。
2. 独立项目材料仓库保存生成结果和版本记录，标识已完成、需申请人确认以及历史版本。
3. 申请人使用当前官方系统填写申请表并核实权利主体、开发完成日期、发表情况及实际声明。
4. 如果软件版本变化，应以同一个固定源码快照重新检查源程序与说明书，而非把不同版本的内容混用。

## 法定材料与内部质量控制

申请表、鉴别材料及适用的证明文件是核心申报资料。生产部署、真实业务数据库、复杂算法基准测试通常不是普通软件著作权登记的法定必备材料，不得因为这些内部工程检查未完成而自动标记为“不符合软著要求”。

内部质量控制可按项目需要执行，但不能将尚未测试的功能写成已验证、将不存在的代码写成已实现，或将 AI 实际参与的工作描述为未使用 AI。

对于涉及商业秘密的源程序，需要评估适用的交存处理方式；不要直接覆盖真实代码或隐瞒敏感内容来源。

具体官方办理要求以提交时的登记系统和登记机构说明为准。
